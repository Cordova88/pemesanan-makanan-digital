# Modul 1. Class dan Object

[Kembali ke indeks OOP](README.md). Mengikuti kode proyek utama pada 23 Oktober 2026.

Bayangkan ada dua menu: nasi goreng dan es teh. Keduanya mempunyai nama dan harga, tetapi
nilainya berbeda. Kita bisa memakai satu class untuk menentukan data dan kemampuan yang
dimiliki menu. Dari class itu, program membuat object untuk masing-masing menu. Lima contoh
berikut menunjukkan bahwa object juga bisa dipakai untuk keranjang, batas harga, hak pengguna,
dan pilihan makanan.

## Yang akan dipelajari

- Memahami masalah lewat contoh sebelum membaca kode.
- Menunjuk data dan method yang benar-benar dipakai pada lima berkas.
- Menjelaskan cara kerjanya dengan kata sendiri dan menyebutkan batasnya.

## Arti istilah yang diperlukan

| Istilah | Penjelasan sederhana |
|---|---|
| Class | Rancangan yang menentukan data dan pekerjaan yang dimiliki sesuatu dalam program. |
| Object | Sesuatu yang dibuat dari class. Dua object dapat memakai class yang sama tetapi menyimpan nilai berbeda. |
| Atribut | Data milik object, misalnya nama atau harga. |
| Method | Fungsi di dalam class, misalnya menghitung harga atau mengosongkan keranjang. |
| self dan __init__ | self menunjuk object yang sedang dipakai. __init__ menyiapkan data awal ketika object dibuat. |

## Kasus 1. Dua menu berbeda dibuat dari class yang sama

**Buka berkas:** [menu/models.py](../../menu/models.py#L48). **Class atau method yang
dibahas:** `MenuItem`.

### Masalah yang dihadapi

Staf memasukkan nasi goreng dan es teh. Keduanya perlu mempunyai nama, harga, kategori, dan
keterangan tersedia atau habis. Daripada membuat susunan kode berbeda untuk setiap makanan,
proyek memakai satu class bernama `MenuItem`.

### Cuplikan kode nyata

Potongan berikut berasal dari `MenuItem.__str__`. Bagian lain dapat dibaca pada berkas aslinya.

```python
def __str__(self) -> str:
    return self.name
```

### Ikuti kode langkah demi langkah

1. Temukan `class MenuItem(models.Model)`. Itu nama rancangan untuk data menu.
2. Lihat `name`, `price`, dan `category`. Ketiganya menentukan data yang dimiliki menu.
3. Baca `__str__`. Method ini mengambil nama dari object yang sedang dipakai.
4. Baca `save`. Perhatikan pekerjaan foto sebelum penyimpanan diteruskan ke Django.

### Contoh masukan dan hasilnya

Bayangkan object nasi bernama "Nasi" dengan harga Rp18.000 dan object teh bernama "Teh" dengan
harga Rp5.000. Keduanya memakai class MenuItem. Mengubah nama nasi tidak mengganti nama teh.
Untuk menyimpan contoh ini ke database, kategori dan data wajib lain tetap harus dilengkapi.

### Mengapa ini contoh OOP?

Class dapat diibaratkan sebagai formulir kosong. Setiap object adalah satu formulir yang sudah
diisi untuk satu menu. Method yang sama membaca data object yang sedang dipakai melalui `self`.
Karena itu `__str__` dapat menampilkan nama nasi goreng atau es teh tanpa membuat dua fungsi
yang berbeda.

### Hal yang perlu diingat

Membuat `MenuItem(...)` belum menyimpan menu ke database. Agar menu benar-benar tersimpan, data
wajib seperti kategori harus dilengkapi dan alur penyimpanan dijalankan. Bedakan membuat object
di memori dengan menyimpan menu yang nanti muncul di web.

### Coba jelaskan kembali

benar-benar masuk ke database?

## Kasus 2. Dua pelanggan mempunyai batas harga berbeda

**Buka berkas:**
[recommendation/services/budget.py](../../recommendation/services/budget.py#L53). **Class atau
method yang dibahas:** `BudgetConstraint`.

### Masalah yang dihadapi

Pelanggan pertama hanya ingin menu sampai Rp10.000. Pelanggan kedua masih bersedia membayar
sampai Rp20.000. Program perlu menyimpan batas mereka secara terpisah supaya pilihan satu
pelanggan tidak tertukar dengan yang lain.

### Cuplikan kode nyata

Potongan berikut berasal dari `BudgetConstraint.allows`. Bagian lain dapat dibaca pada berkas
aslinya.

```python
def allows(self, price: Decimal) -> bool:
    if self.minimum is not None and (
        price < self.minimum or (price == self.minimum and not self.minimum_inclusive)
    ):
        return False

    if self.maximum is not None and (
        price > self.maximum or (price == self.maximum and not self.maximum_inclusive)
    ):
        return False

    return True
```

### Ikuti kode langkah demi langkah

1. Lihat batas minimum dan maksimum yang diterima `__init__`.
2. Perhatikan pemeriksaan nilai sebelum data disimpan pada object.
3. Lihat property `minimum` dan `maximum` untuk membaca batas.
4. Baca `allows`. Bandingkan harga masukan dengan batas yang disimpan.

### Contoh masukan dan hasilnya

Buat budget pertama dengan batas Rp10.000 dan budget kedua Rp20.000. Harga Rp15.000 ditolak
oleh budget pertama dan diterima oleh budget kedua. Method allows sama; yang berbeda adalah
data batas pada masing-masing object.

### Mengapa ini contoh OOP?

`BudgetConstraint` menyatukan batas harga dengan cara memeriksanya. Dua object dapat memakai
method `allows` yang sama, tetapi memberikan jawaban berbeda karena batas yang disimpan
berbeda. Jadi, hasil method tidak hanya ditentukan nama class, melainkan juga data object yang
menerima panggilan.

### Hal yang perlu diingat

Object ini hanya menyimpan aturan pencarian harga. Ia tidak menyimpan uang pelanggan, memotong
saldo, atau membayar pesanan. Contoh angka pada materi adalah angka latihan.

### Coba jelaskan kembali

Mengapa harga Rp15.000 ditolak oleh satu object budget tetapi diterima object yang lain?

## Kasus 3. Isi keranjang mengikuti sesi browser

**Buka berkas:** [cart/services.py](../../cart/services.py#L25). **Class atau method yang
dibahas:** `CartService`.

### Masalah yang dihadapi

Dua browser dapat membuka web yang sama dan memilih makanan berbeda. `CartService` menerima
sesi browser yang akan dipakai. Sesi adalah tempat aplikasi menyimpan data sementara, misalnya
isi keranjang pelanggan.

### Cuplikan kode nyata

Potongan berikut berasal dari `CartService.__init__`. Bagian lain dapat dibaca pada berkas
aslinya.

```python
def __init__(self, session: SessionBase) -> None:
    self.session: SessionBase = session
    self._lines: list[CartLine] = deepcopy(session.get(self.SESSION_KEY, []))
```

### Ikuti kode langkah demi langkah

1. Temukan `SESSION_KEY`. Nilainya adalah nama kunci penyimpanan, yaitu cart.
2. Baca `__init__` untuk melihat sesi yang diberikan dan isi keranjang yang dibaca.
3. Baca `_save` untuk melihat cara mengembalikan perubahan ke sesi.
4. Bandingkan `add_item` dan `clear`: keduanya mengerjakan keranjang yang diterima object itu.

### Contoh masukan dan hasilnya

Browser A berisi dua nasi, sedangkan browser B berisi satu teh. Jika masing-masing memakai sesi
berbeda, mengosongkan keranjang A tidak mengosongkan B. Namun dua CartService yang diberi sesi
sama tetap menunjuk penyimpanan keranjang yang sama.

### Mengapa ini contoh OOP?

Object layanan menghubungkan pekerjaan dengan data yang akan dikerjakan. `self.session`
menunjuk sesi yang dipakai, sedangkan `self._lines` berisi salinan baris keranjang. Nama kunci
penyimpanannya sama, yaitu `cart`, tetapi isi masing-masing sesi dapat berbeda.

### Hal yang perlu diingat

Dua object `CartService` tidak selalu berarti dua pelanggan. Jika keduanya diberi sesi yang
sama, keduanya mengarah ke keranjang yang sama. Salinan data juga tidak otomatis mengatur dua
perubahan yang dikirim pada waktu bersamaan.

### Coba jelaskan kembali

Apa bedanya dua CartService yang menerima sesi berbeda dan dua CartService yang menerima sesi
yang sama?

## Kasus 4. Pemeriksaan akses mengikuti pengguna yang diberikan

**Buka berkas:** [users/access.py](../../users/access.py#L18). **Class atau method yang
dibahas:** `StaffAccess`.

### Masalah yang dihadapi

Seorang staf boleh mengelola katalog. Kasir biasa boleh membuka halaman kasir, tetapi belum
tentu boleh mengubah menu. `StaffAccess` menerima pengguna yang ingin diperiksa, lalu
menyediakan jawaban atas pertanyaan akses tersebut.

### Cuplikan kode nyata

Potongan berikut berasal dari `StaffAccess.can_use_cashier`. Bagian lain dapat dibaca pada
berkas aslinya.

```python
@property
def can_use_cashier(self) -> bool:
    return self._user.is_authenticated and (self._user.is_staff or self.is_cashier)
```

### Ikuti kode langkah demi langkah

1. Baca `__init__` dan temukan pengguna yang disimpan pada `_user`.
2. Baca `can_manage_catalog`: pengguna harus login dan berstatus staf.
3. Baca `is_cashier`: lihat pemeriksaan grup Cashier.
4. Baca `can_use_cashier` dan `home_route` untuk membedakan izin dengan halaman tujuan.

### Contoh masukan dan hasilnya

Staf yang sudah login dapat mengelola katalog. Kasir biasa yang masuk grup Cashier dapat
memakai halaman kasir, tetapi tidak otomatis boleh mengubah menu. Pengguna yang belum login
tidak mendapat akses operator hanya karena mengetahui alamat halamannya.

### Mengapa ini contoh OOP?

Object ini mengelompokkan aturan tentang pengguna yang sama. Program bisa membaca
`can_manage_catalog` atau `can_use_cashier` tanpa menulis ulang pemeriksaan grup dan status
staf di setiap tempat. `self._user` membuat keputusan itu selalu memakai pengguna yang
diberikan kepada object tersebut.

### Hal yang perlu diingat

Membuat object `StaffAccess` tidak membuat akun, melakukan login, atau memberikan izin baru.
Tombol yang disembunyikan juga belum cukup; bagian server yang menerima tindakan tetap harus
memeriksa hak pengguna.

### Coba jelaskan kembali

Mengapa object pengguna dan object pemeriksa akses mempunyai pekerjaan yang berbeda?

## Kasus 5. Pilihan pelanggan tidak perlu menjadi menu baru

**Buka berkas:** [menu/selection.py](../../menu/selection.py#L34). **Class atau method yang
dibahas:** `MenuSelection`.

### Masalah yang dihadapi

Dua pelanggan memilih menu nasi yang sama. Yang satu memilih ukuran besar dan telur, yang lain
memilih ukuran biasa tanpa tambahan. Katalog menunya tetap satu; yang berbeda adalah pilihan
pelanggan.

### Cuplikan kode nyata

Potongan berikut berasal dari `MenuSelection.__init__`. Bagian lain dapat dibaca pada berkas
aslinya.

```python
def __init__(
    self,
    item: MenuItem,
    options: Iterable[VariantOption] = (),
    addons: Iterable[AddOn] = (),
) -> None:
    self.item: MenuItem = item
    self.__options: tuple[VariantOption, ...] = tuple(options)
    self.__addons: tuple[AddOn, ...] = tuple(addons)
```

### Ikuti kode langkah demi langkah

1. Lihat masukan `item`, `options`, dan `addons` pada `__init__`.
2. Perhatikan daftar opsi dan tambahan diubah menjadi tuple, yaitu daftar yang anggotanya tidak ditambah lewat append.
3. Baca `from_ids` untuk melihat pemeriksaan pilihan berdasarkan katalog.
4. Baca `unit_price` dan `total_price` untuk melihat harga satu porsi dan beberapa porsi.

### Contoh masukan dan hasilnya

Harga dasar Rp18.000 ditambah varian Rp2.000 dan addon Rp3.000 menghasilkan Rp23.000 per porsi.
Untuk dua porsi, totalnya Rp46.000. Pelanggan lain yang tidak memilih addon dapat memakai menu
yang sama dengan harga pilihan berbeda.

### Mengapa ini contoh OOP?

`MenuSelection` menyatukan menu, varian, dan tambahan yang sedang dipilih. Object ini juga
menyediakan perhitungan harga. Ini menunjukkan bahwa class tidak harus selalu membuat tabel
database. Class biasa dapat dipakai untuk membawa data yang berkaitan dan menghitung hasilnya.

### Hal yang perlu diingat

Pilihan ini belum menjadi pesanan yang tersimpan. Memanggil pembuatan object secara langsung
hanya menampung pilihan; `from_ids` memeriksa apakah pilihan itu benar-benar boleh dipakai pada
menu tersebut. Saat checkout, server tetap memeriksa kembali harga dan pilihan.

### Coba jelaskan kembali

Gambar dua pilihan pelanggan yang menunjuk menu yang sama. Data mana yang sama dan mana yang
berbeda?
