# Modul 5. Inheritance

[Kembali ke indeks OOP](README.md). Diselaraskan dengan source project utama, 23 Oktober 2026.

Widget foto memerlukan perilaku input file Django sekaligus konteks tambahan untuk preview. Menulis ulang seluruh framework bukan pilihan yang diperlukan: turunan dapat mempertahankan perilaku induk dan menambahkan bagian khusus. Modul ini memeriksa lima berkas, termasuk batas inheritance yang hanya diwarisi dari Django.

## Tujuan pembelajaran

- Mengidentifikasi superclass dan subclass nyata.
- Membaca override dan super berdasarkan urutan pekerjaan, bukan sekadar menandai kata kunci.
- Membedakan perilaku tim, perilaku framework, dan perangkaian object biasa.

## Bekal istilah

| Istilah | Makna saat membaca kode |
|---|---|
| Superclass/subclass | Class induk dan class yang mewarisi kontrak/perilakunya. |
| Override | Turunan menyediakan implementasi method dengan nama yang diwarisi. |
| super() | Meneruskan pencarian implementasi berikutnya menurut MRO. |
| MRO | Urutan pencarian method; bukan selalu berarti memanggil induk bernama tertentu secara langsung. |

## Kasus 1. GeminiClient mengimplementasikan kontrak TextGenerator

**Berkas utama:** [recommendation/services/gemini.py](../../recommendation/services/gemini.py#L61). **Simbol yang dibedah:** `GeminiClient.generate`.

### Masalah yang dihadapi

Pemakai generator membutuhkan method generate yang konsisten tanpa harus mengetahui pemanggilan SDK Google. GeminiClient merupakan turunan konkret yang mengisi pekerjaan tersebut dan menambahkan kemampuan khusus provider.

### Cuplikan kode nyata

Cuplikan `GeminiClient.generate` dari source saat penyelarasan. Import dan bagian lain tidak ditampilkan.

```python
@override
def generate(self, prompt: str) -> str | None:
    return self._generate(prompt, structured_ranking=False)
```

### Bedah alur dan tanggung jawab

1. Baca deklarasi GeminiClient(TextGenerator).
2. Bandingkan signature generate dengan abstractmethod pada induk.
3. Ikuti generate menuju _generate untuk melihat validasi dan dispatch.
4. Cari @override sebagai penanda maksud, lalu bedakan converse yang merupakan kemampuan tambahan.

### Contoh input dan hasil yang perlu dijelaskan

Pemanggil generate menerima str ketika respons dapat digunakan atau None ketika adapter menilai generation tidak tersedia/gagal. Ketika kuota menolak, helper membentuk metadata tetapi tidak memanggil SDK. Pada jalur converse setiap putaran tool juga diperiksa kuotanya sebelum SDK.

### Hubungan dengan konsep OOP

Inheritance menyatakan bahwa adapter menyediakan kemampuan tipe dasarnya. Detail konfigurasi, pencatatan token, dan SDK merupakan implementasi turunan. @override membantu alat analisis memeriksa maksud override; annotation sendiri tidak memvalidasi semua hasil AI.

### Batas penerapan dan kekeliruan yang perlu dihindari

generate tidak perlu memanggil super().generate karena method abstrak induk hanya melempar NotImplementedError. Menambahkan converse tidak memperluas janji semua TextGenerator. Jangan mengganti provider AI-first dengan generator sempit lalu menganggap inheritance sudah cukup.

### Latihan penelusuran

Mengapa override generate tidak memanggil super? Apa beda method turunan tambahan dan method yang dijanjikan induk?

## Kasus 2. TurnGenerator mewarisi kontrak sambil membungkus provider

**Berkas utama:** [recommendation/services/ai/turn_generator.py](../../recommendation/services/ai/turn_generator.py#L69). **Simbol yang dibedah:** `TurnGenerator`.

### Masalah yang dihadapi

Beberapa komponen hybrid dapat ingin memakai bantuan AI pada satu balasan. Wrapper ini menyediakan antarmuka generator yang sama, tetapi membatasi reservasi dan satu percobaan sehingga pekerjaan tidak diam-diam bertambah lewat banyak pemakai.

### Cuplikan kode nyata

Cuplikan `TurnGenerator._generate` dari source saat penyelarasan. Import dan bagian lain tidak ditampilkan.

```python
def _generate(self, prompt: str, *, ranking: bool) -> str | None:
    if self._private or not self._reserved or self._attempted:
        return None

    # Claim before dispatch; exceptions and invalid results cannot refund it.
    self._attempted = True

    try:
        if ranking and isinstance(self.provider, TextGenerator):
            return self.provider.generate_ranking(prompt)

        return self.provider.generate(prompt)
    except Exception:
        return None
```

### Bedah alur dan tanggung jawab

1. Baca TurnGenerator(TextGenerator) dan self.provider.
2. Ikuti reset yang menyiapkan _reserved, _attempted, dan _private.
3. Baca reserve serta reservation_block_reason sebelum generate.
4. Ikuti _generate yang menandai percobaan sebelum meneruskan ke provider.

### Contoh input dan hasil yang perlu dijelaskan

Sesudah reserve berhasil, pemanggilan generate pertama dapat meneruskan ke provider. Pemanggilan kedua mengembalikan None karena _attempted sudah True. Error provider tidak memberi jatah ulang otomatis. Membaca protect memperlihatkan gate data sensitif pada jalur yang memang memakai wrapper ini.

### Hubungan dengan konsep OOP

Di sini inheritance menjamin bentuk generate, sedangkan komposisi object menyediakan alat yang dibungkus. Wrapper bisa menambahkan kebijakan tanpa menulis ulang provider. Penambahan perilaku harus tetap dijelaskan sebagai prasyarat wrapper kepada pemakai yang mereservasinya.

### Batas penerapan dan kekeliruan yang perlu dihindari

Aturan satu percobaan ini bukan aturan semua chat AI-first. GeminiAssistant memanggil converse langsung pada provider dan boleh memiliki beberapa putaran tool yang dibatasi. Perlindungan _private wrapper juga tidak otomatis mencakup jalur langsung tersebut.

### Latihan penelusuran

Gambar urutan reserve → generate → generate kedua. Mengapa provider field bukan superclass lain?

## Kasus 3. MenuItem memperluas save milik model Django

**Berkas utama:** [menu/models.py](../../menu/models.py#L71). **Simbol yang dibedah:** `MenuItem.save`.

### Masalah yang dihadapi

Unggahan foto perlu diproses sebelum disimpan agar katalog mempunyai format hasil yang konsisten. MenuItem mewarisi ORM Django dan meng-override save untuk menambahkan pekerjaan foto, lalu meneruskan penyimpanan normal ke framework.

### Cuplikan kode nyata

Cuplikan `MenuItem.save` dari source saat penyelarasan. Import dan bagian lain tidak ditampilkan.

```python
def save(self, *args: object, **kwargs: object) -> None:
    update_fields = kwargs.get("update_fields")

    for field_name in ("image", "detail_image"):
        image = getattr(self, field_name)

        if (
            image
            and not image._committed
            and (update_fields is None or field_name in update_fields)
        ):
            from .image_processing import archive_original, prepare_photo

            photo = prepare_photo(image.file)
            archive_original(photo)
            setattr(self, field_name, photo)

    return super().save(*args, **kwargs)
```

### Bedah alur dan tanggung jawab

1. Baca superclass models.Model dan field image/detail_image.
2. Ikuti loop dua field foto serta pemeriksaan image._committed.
3. Lihat prepare_photo dan archive_original sebelum field diganti hasil pemrosesan.
4. Temukan return super().save(*args, **kwargs) pada akhir alur.

### Contoh input dan hasil yang perlu dijelaskan

Jika instans menerima unggahan baru pada field yang sedang disimpan, foto diproses dan aslinya diarsipkan sebelum penyimpanan model dilanjutkan. Jika hanya update_fields tertentu dan foto tidak termasuk, kondisi mencegah pemrosesan yang tidak diperlukan. Parser yang dipilih pemroses kini hanya JPEG, PNG, dan WEBP.

### Hubungan dengan konsep OOP

Turunan menambahkan perilaku khusus domain sambil mempertahankan mekanisme simpan induk. Metode inherited seperti query manager berasal dari framework; jangan mengklaim tim menulis ORM. super menjaga kelanjutan alur sesuai MRO dan parameter yang diterima.

### Batas penerapan dan kekeliruan yang perlu dihindari

save dapat mempunyai efek file dan database; jangan menjalankannya pada data kerja hanya untuk belajar override. Tidak semua operasi bulk ORM memanggil override save per instans. Validasi model juga tidak otomatis lengkap hanya karena save diwarisi.

### Latihan penelusuran

Apa yang hilang jika super().save tidak dipanggil? Mengapa update_fields diperiksa sebelum mengolah foto?

## Kasus 4. MenuPhotoForm menambahkan atribut setelah constructor induk

**Berkas utama:** [menu/forms.py](../../menu/forms.py#L34). **Simbol yang dibedah:** `MenuPhotoForm.__init__`.

### Masalah yang dihadapi

Editor foto membutuhkan ID menu pada atribut widget. Form model tetap membutuhkan fields dan instance yang disiapkan Django. Karena itu constructor turunan harus menyelesaikan inisialisasi framework sebelum mengakses self.fields dan self.instance.

### Cuplikan kode nyata

Cuplikan `MenuPhotoForm.__init__` dari source saat penyelarasan. Import dan bagian lain tidak ditampilkan.

```python
def __init__(self, *args: object, **kwargs: object) -> None:
    super().__init__(*args, **kwargs)
    self.fields["image"].widget.attrs["data_menu_id"] = self.instance.pk or ""
    self.fields["detail_image"].widget.attrs["data_menu_id"] = self.instance.pk or ""
```

### Bedah alur dan tanggung jawab

1. Baca MenuPhotoForm(forms.ModelForm) dan Meta.model.
2. Perhatikan super().`__init__`(*args, **kwargs) dipanggil lebih dahulu.
3. Ikuti pengisian data_menu_id pada widget image/detail_image.
4. Baca clean_image dan _clean_photo untuk membedakan inisialisasi dengan validasi unggahan.

### Contoh input dan hasil yang perlu dijelaskan

Pada edit menu tersimpan, data_menu_id memakai primary key instance. Pada form baru, self.instance.pk belum ada sehingga atribut memakai string kosong. Ini tidak berarti constructor membuat record database baru; form hanya disiapkan untuk input/render/validasi sesuai alur pemanggil.

### Hubungan dengan konsep OOP

Inheritance mengizinkan penyesuaian kecil di atas perilaku ModelForm. super bukan dekorasi: ia menyiapkan state yang dipakai turunan. Perluasan terletak pada metadata widget, sedangkan binding data, fields, dan mekanisme validasi model form tetap memakai Django.

### Batas penerapan dan kekeliruan yang perlu dihindari

Menghapus super lalu tetap memakai self.fields dapat merusak inisialisasi. Atribut HTML data_menu_id bukan izin edit dan tidak boleh dipakai sebagai satu-satunya otorisasi. Form juga mengandalkan validator/pemroses server meskipun accept pada browser membatasi pilihan UI.

### Latihan penelusuran

Jelaskan urutan pembuatan form baru dan form edit. Mengapa instance.pk dapat kosong tanpa dianggap error?

## Kasus 5. MenuPhotoWidget memperluas konteks render induk

**Berkas utama:** [menu/widgets.py](../../menu/widgets.py#L12). **Simbol yang dibedah:** `MenuPhotoWidget.get_context`.

### Masalah yang dihadapi

Input file biasa belum mempunyai informasi preview foto yang dibutuhkan template proyek. MenuPhotoWidget mewarisi ClearableFileInput dan menambah photo_url tanpa membuang struktur context yang dipakai framework.

### Cuplikan kode nyata

Cuplikan `MenuPhotoWidget.get_context` dari source saat penyelarasan. Import dan bagian lain tidak ditampilkan.

```python
def get_context(
    self,
    name: str,
    value: File | None,
    attrs: dict[str, object] | None,
) -> dict[str, object]:
    context = super().get_context(name, value, attrs)
    context["widget"]["photo_url"] = value.url if value and hasattr(value, "url") else ""

    return context
```

### Bedah alur dan tanggung jawab

1. Baca superclass dan template_name.
2. Periksa class Media yang menyertakan CSS/JavaScript editor foto.
3. Ikuti context=super().get_context(name, value, attrs).
4. Baca kondisi value dan hasattr(value, "url") sebelum memasukkan photo_url.

### Contoh input dan hasil yang perlu dijelaskan

Jika value merupakan file tersimpan yang memiliki url, context widget memuat URL tersebut untuk preview. Jika belum ada file, photo_url menjadi string kosong. Framework tetap menerima bagian context bawaan, sehingga atribut input, nama field, dan perilaku clear dapat tetap dirender oleh template yang sesuai.

### Hubungan dengan konsep OOP

Override ini memperluas hasil method induk, berbeda dari generate pada adapter yang mengganti implementasi abstrak. Mengetahui perbedaan tersebut membantu menentukan kapan super diperlukan. Runtime memilih method widget turunan ketika form merender field yang memakai widget ini.

### Batas penerapan dan kekeliruan yang perlu dihindari

Widget mengatur tampilan input, bukan validasi aman seluruh isi file. URL kosong tidak berarti foto dihapus dari database. Validasi parser, byte, dan piksel dilakukan di pemroses server; jangan memindahkan tanggung jawab itu ke JavaScript editor.

### Latihan penelusuran

Mengapa membuat dictionary context baru dari nol dapat menghilangkan perilaku bawaan? Bedakan widget dan form pada alur unggah.
