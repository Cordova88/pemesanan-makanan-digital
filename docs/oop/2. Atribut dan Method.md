# Modul 2. Atribut dan Method

[Kembali ke indeks OOP](README.md). Mengikuti kode proyek utama pada 23 Oktober 2026.

Satu object keranjang mempunyai data dan pekerjaan. Datanya antara lain sesi browser dan daftar
makanan. Pekerjaannya antara lain menambah makanan, memeriksa jumlah, dan mengosongkan
keranjang. Modul ini mengajak kita memilih cara penulisan berdasarkan apa yang dibutuhkan suatu
pekerjaan, bukan sekadar menghafal nama decorator.

## Yang akan dipelajari

- Memahami masalah lewat contoh sebelum membaca kode.
- Menunjuk data dan method yang benar-benar dipakai pada lima berkas.
- Menjelaskan cara kerjanya dengan kata sendiri dan menyebutkan batasnya.

## Arti istilah yang diperlukan

| Istilah | Penjelasan sederhana |
|---|---|
| Atribut class | Data yang disediakan pada rancangan class, misalnya nama kunci penyimpanan. |
| Atribut object | Data milik object tertentu, misalnya isi satu keranjang. |
| Instance method | Method yang memakai self untuk bekerja dengan data suatu object. |
| classmethod | Method yang memakai cls, biasanya untuk membuat object dari bentuk data lain. |
| staticmethod | Method yang cukup bekerja dari nilai masukan, tanpa self atau cls. |
| property | Method yang dibaca seperti atribut. Contohnya selection.unit_price, tanpa tanda kurung di belakangnya. |

## Kasus 1. Nama penyimpanan sama, isi keranjang berbeda

**Buka berkas:** [cart/services.py](../../cart/services.py#L20). **Class atau method yang
dibahas:** `CartService`.

### Masalah yang dihadapi

Semua keranjang memakai nama penyimpanan `cart`. Namun daftar makanan setiap pelanggan bisa
berbeda. Selain itu, pemeriksaan jumlah porsi hanya membutuhkan angka yang dimasukkan, bukan
seluruh isi keranjang.

### Cuplikan kode nyata

Potongan berikut berasal dari `CartService._validate_quantity`. Bagian lain dapat dibaca pada
berkas aslinya.

```python
@staticmethod
def _validate_quantity(quantity: object) -> None:
    if type(quantity) is not int or not 1 <= quantity <= 99:
        raise ValidationError({"quantity": "Jumlah porsi harus 1 sampai 99."})
```

### Ikuti kode langkah demi langkah

1. Bedakan `SESSION_KEY` yang tertulis pada class dengan `session` dan `_lines` milik setiap object.
2. Lihat `@staticmethod` di atas `_validate_quantity`.
3. Perhatikan angka harus benar-benar int dan berada pada 1–99.
4. Bandingkan dengan `clear`, yang membutuhkan self untuk mengetahui keranjang mana yang dikosongkan.

### Contoh masukan dan hasilnya

Jumlah 99 diterima. Jumlah 100, True, dan teks "2" ditolak. Saat jumlah 98 ditambah 2 pada
baris yang sama, hasil 100 diperiksa sebelum disimpan. Karena ditolak, jumlah lama tetap 98.

### Mengapa ini contoh OOP?

Pekerjaan yang memerlukan data object memakai `self`. Contohnya `clear` harus tahu keranjang
mana yang dikosongkan. Sebaliknya, `_validate_quantity` cukup menerima satu nilai. Karena itu
ia memakai `staticmethod`. Memilih jenis method berdasarkan kebutuhan membuat alasannya lebih
mudah dijelaskan.

### Hal yang perlu diingat

`ClassVar` adalah keterangan bagi pembaca dan alat pemeriksa kode. Keterangan itu sendiri tidak
membuat tempat penyimpanan baru. Batas jumlah juga perlu dibaca sesuai tindakan: pada
`update_quantity`, angka bulat nol atau kurang berarti menghapus baris.

### Coba jelaskan kembali

Mengapa pemeriksaan jumlah cukup menerima satu angka, sedangkan clear harus memakai self?

## Kasus 2. Membuat object budget dari data tersimpan

**Buka berkas:**
[recommendation/services/budget.py](../../recommendation/services/budget.py#L81). **Class atau
method yang dibahas:** `BudgetConstraint.from_dict`.

### Masalah yang dihadapi

Data sesi disimpan dalam bentuk sederhana. Saat hendak dipakai menghitung, data itu perlu
dibaca kembali sebagai object budget. Method `from_dict` membuat object tersebut dan tetap
memeriksa isinya.

### Cuplikan kode nyata

Ini bagian awal `BudgetConstraint.from_dict`. Lanjutkan ke berkas aslinya untuk membaca seluruh
method. Bagian import tidak ditampilkan.

```python
@classmethod
def from_dict(cls, data: BudgetPayload) -> Self:
    try:
        if set(data) != {"minimum", "maximum", "minimum_inclusive", "maximum_inclusive"}:
            raise ValueError("Invalid budget fields")

        if any(
            type(data[key]) is not bool for key in ("minimum_inclusive", "maximum_inclusive")
        ):
            raise ValueError("Invalid budget flags")

        if any(
            data[key] is not None and not isinstance(data[key], str)
            for key in ("minimum", "maximum")
        ):
            raise ValueError("Invalid budget amount")

        return cls(
```

### Ikuti kode langkah demi langkah

1. Temukan `@classmethod` dan nama `cls` pada `from_dict`.
2. Baca pemeriksaan nama data, angka berbentuk teks, dan nilai True/False.
3. Ikuti perubahan teks angka menjadi Decimal.
4. Bandingkan dengan `to_dict`, yang membaca object yang sudah ada untuk disimpan.

### Contoh masukan dan hasilnya

Data dengan maximum="20000" dapat dipakai membentuk budget jika semua bagian lain sesuai.
Maximum berupa angka 20000 ditolak pada pembacaan ini karena bentuk yang disimpan ditentukan
berupa teks. Minimum Rp30.000 dengan maksimum Rp20.000 tetap ditolak oleh pemeriksaan awal
object.

### Mengapa ini contoh OOP?

`from_dict` memakai `cls`, yang berarti class yang sedang diminta membuat object. Ia berbeda
dengan `to_dict`, yang memakai `self` karena membaca budget yang sudah ada. Dengan
membandingkan kedua method ini, kita bisa melihat bedanya membuat object baru dan membaca
object lama.

### Hal yang perlu diingat

Bentuk data tetap penting. Angka batas harga pada dictionary ini disimpan sebagai teks atau
None, sedangkan tanda boleh-tidaknya menyertakan batas harus berupa True atau False. Nama jenis
data pada kode tidak menggantikan pemeriksaan isinya.

### Coba jelaskan kembali

## Kasus 3. Merapikan alias cukup memakai teks masukan

**Buka berkas:** [menu/models.py](../../menu/models.py#L106). **Class atau method yang
dibahas:** `MenuItemAlias.normalize_phrase`.

### Masalah yang dihadapi

Staf bisa menulis alias dengan huruf besar dan spasi berlebih. Program perlu merapikannya agar
mudah dibandingkan. Untuk pekerjaan ini, kita hanya membutuhkan teks, belum membutuhkan menu
yang tersimpan.

### Cuplikan kode nyata

Potongan berikut berasal dari `MenuItemAlias.normalize_phrase`. Bagian lain dapat dibaca pada
berkas aslinya.

```python
@staticmethod
def normalize_phrase(value: str) -> str:
    return " ".join(value.casefold().split())
```

### Ikuti kode langkah demi langkah

1. Lihat `@staticmethod` pada `normalize_phrase`.
2. Ikuti `casefold`, lalu `split` dan `join` untuk merapikan huruf dan spasi.
3. Baca `clean`: hasilnya dipakai memperbarui phrase pada object.
4. Baca `save`: pemeriksaan clean dilakukan sebelum penyimpanan Django.

### Contoh masukan dan hasilnya

Teks "  AYAM   Geprek  " menjadi "ayam geprek". Langkah merapikan teks ini tidak membutuhkan
menu tersimpan. Ketika clean memakainya, phrase pada satu object diubah; menyimpannya ke
database tetap memerlukan langkah save.

### Mengapa ini contoh OOP?

`normalize_phrase` ditulis sebagai `staticmethod` karena hasilnya cukup dihitung dari teks
masukan. Saat method `clean` memakai hasilnya untuk mengubah `self.phrase`, barulah data satu
object diubah. Dua pekerjaan ini berkaitan, tetapi kebutuhan datanya berbeda.

### Hal yang perlu diingat

Teks yang sudah rapi belum tentu hanya dimiliki satu menu. Dua menu bisa mempunyai sebutan
serupa. Karena itu merapikan teks belum sama dengan menentukan menu mana yang dimaksud
pelanggan.

### Coba jelaskan kembali

Bagian mana yang hanya menghasilkan teks baru dan bagian mana yang mengubah data object?

## Kasus 4. Membaca harga satuan dan menghitung harga beberapa porsi

**Buka berkas:** [menu/selection.py](../../menu/selection.py#L101). **Class atau method yang
dibahas:** `MenuSelection.unit_price`.

### Masalah yang dihadapi

Halaman perlu menampilkan harga satu porsi, lalu menghitung total jika pelanggan memilih dua
porsi. Harga satuan sudah bisa dihitung dari pilihan yang tersimpan. Total beberapa porsi masih
membutuhkan jumlah sebagai masukan.

### Cuplikan kode nyata

Potongan berikut berasal dari `MenuSelection.unit_price`. Bagian lain dapat dibaca pada berkas
aslinya.

```python
@property
def unit_price(self) -> Decimal:
    return (
        self.item.price
        + sum((option.price_adjustment for option in self.__options), Decimal())
        + sum((addon.price for addon in self.__addons), Decimal())
    )
```

### Ikuti kode langkah demi langkah

1. Lihat `@property` di atas `unit_price`.
2. Pisahkan harga dasar, harga varian, dan harga tambahan pada perhitungannya.
3. Baca `total_price(quantity)` dan pemeriksaan jumlah 1–99.
4. Bandingkan penulisan `selection.unit_price` dengan `selection.total_price(2)`.

### Contoh masukan dan hasilnya

Dengan harga pilihan Rp23.000, selection.unit_price menghasilkan Rp23.000 dan
selection.total_price(2) menghasilkan Rp46.000. Jangan menulis selection.unit_price() karena
hasilnya adalah nilai harga, bukan fungsi yang perlu dipanggil lagi.

### Mengapa ini contoh OOP?

`unit_price` memakai `property`, sehingga dibaca seperti data biasa. `total_price` memakai
Parameter jumlah, sehingga dipanggil sebagai method. Keduanya memakai data pilihan yang sama.
Perbedaan penulisan ini membantu pembaca melihat kapan cukup membaca nilai dan kapan harus
memberi masukan tambahan.

### Hal yang perlu diingat

Property tidak otomatis menyimpan hasil hitungan selamanya. Saat dibaca lagi, nilainya dapat
dihitung lagi. Harga akhir juga masih mengikuti pemeriksaan server ketika pesanan dibuat.

### Coba jelaskan kembali

Mengapa selection.unit_price tidak memakai tanda kurung, sedangkan selection.total_price(2)
memakainya?

## Kasus 5. Siap memakai Gemini berbeda dengan benar-benar memanggil Gemini

**Buka berkas:**
[recommendation/services/gemini.py](../../recommendation/services/gemini.py#L29). **Class atau
method yang dibahas:** `GeminiClient.available`.

### Masalah yang dihadapi

Program perlu tahu apakah Gemini sudah diaktifkan dan object penghubungnya sudah tersedia.
Mengetahui keadaan itu berbeda dengan mengirim pesan yang benar-benar menggunakan kuota.

### Cuplikan kode nyata

Potongan berikut berasal dari `GeminiClient.available`. Bagian lain dapat dibaca pada berkas
aslinya.

```python
@property
def available(self) -> bool:
    return bool(getattr(settings, 'GEMINI_ENABLED', False) and self.client is not None)
```

### Ikuti kode langkah demi langkah

1. Baca bagian penyiapan object untuk melihat kapan client Gemini dibuat.
2. Baca `available` untuk melihat syarat Gemini dianggap tersedia.
3. Ikuti `generate` dan `converse` untuk melihat kapan layanan benar-benar dipanggil.
4. Temukan pemeriksaan kuota sebelum panggilan dan pencatatan hasil sesudahnya.

### Contoh masukan dan hasilnya

Saat Gemini dimatikan, available bernilai False. Saat aktif dan client tersedia, available
dapat True. Walaupun begitu, panggilan masih bisa ditolak karena kuota habis. Jadi siap
dipakai, sudah dipanggil, dan berhasil menjawab adalah tiga hal berbeda.

### Mengapa ini contoh OOP?

Property `available` menjawab apakah syarat awal terpenuhi. Method `generate` dan `converse`
menjalankan pekerjaan berikutnya, termasuk memeriksa batas penggunaan. Atribut `last_event`
menyimpan catatan panggilan terakhir agar program dapat mengetahui hasilnya.

### Hal yang perlu diingat

`available=True` belum membuktikan sambungan internet atau kunci API pasti benar. Kuota masih
dapat habis dan permintaan masih bisa gagal. Catatan token baru tersedia jika layanan
mengirimkan informasi penggunaannya.

### Coba jelaskan kembali

Apa beda Gemini tersedia, Gemini dipanggil, dan Gemini berhasil memberi jawaban?
