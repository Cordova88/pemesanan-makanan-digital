# Modul 2. Atribut dan Method

[Kembali ke indeks OOP](README.md). Diselaraskan dengan source project utama, 23 Oktober 2026.

Satu layanan keranjang memiliki nama kunci penyimpanan, referensi sesi, dan daftar baris. Ketiganya data, tetapi cakupannya berbeda. Pada modul ini kita membaca alasan suatu perilaku menjadi instance method, classmethod, staticmethod, atau property, lalu menghubungkannya dengan pemanggilan yang benar.

## Tujuan pembelajaran

- Mengelompokkan atribut kelas dan instans berdasarkan tempat penyimpanan serta tujuannya.
- Membaca decorator dan menjelaskan apakah method membutuhkan self, cls, atau hanya parameter.
- Menelusuri perubahan state dan membedakannya dari perhitungan nilai.

## Bekal istilah

| Istilah | Makna saat membaca kode |
|---|---|
| Instance method | Menerima self dan dapat membaca/mengubah state instans. |
| Class method | Menerima cls; berguna untuk factory yang membentuk instans. |
| Static method | Tidak menerima self/cls otomatis; tetap dapat memvalidasi input. |
| Property | Diakses seperti atribut, tetapi nilainya diperoleh melalui method getter. |

## Kasus 1. Atribut kelas dan helper validasi pada keranjang

**Berkas utama:** [cart/services.py](../../cart/services.py#L20). **Simbol yang dibedah:** `CartService`.

### Masalah yang dihadapi

Semua layanan keranjang menyimpan data di kunci cart, tetapi daftar barisnya berbeda per sesi. Selain itu, aturan jumlah porsi tidak perlu bergantung pada satu isi keranjang tertentu. Kode memisahkan nama bersama, state instans, dan validasi yang hanya memerlukan nilai masukan.

### Cuplikan kode nyata

Cuplikan `CartService._validate_quantity` dari source saat penyelarasan. Import dan bagian lain tidak ditampilkan.

```python
@staticmethod
def _validate_quantity(quantity: object) -> None:
    if type(quantity) is not int or not 1 <= quantity <= 99:
        raise ValidationError({"quantity": "Jumlah porsi harus 1 sampai 99."})
```

### Bedah alur dan tanggung jawab

1. Kelompokkan SESSION_KEY sebagai ClassVar, session/_lines sebagai atribut instans.
2. Baca _validate_quantity yang memakai @staticmethod dan parameter quantity.
3. Perhatikan type(quantity) is int: True tidak diterima meskipun bool merupakan turunan int.
4. Bandingkan dengan clear: method ini membutuhkan self karena mengosongkan _lines lalu memanggil _save.

### Contoh input dan hasil yang perlu dijelaskan

CartService._validate_quantity(99) lolos, sedangkan 100, True, dan "2" memunculkan ValidationError. Method tidak mengembalikan angka baru; hasil suksesnya None. Saat add_item menggabungkan 98 dan 2, hasil gabungan diperiksa sebelum _lines diubah, sehingga penolakan tidak menimpa jumlah lama.

### Hubungan dengan konsep OOP

Pemilihan decorator didasarkan pada dependency perilaku. Validasi satu nilai cukup menjadi staticmethod. Mengosongkan keranjang memerlukan state instans dan tetap menjadi instance method. ClassVar merupakan penjelasan tipe untuk pembaca/alat analisis, bukan database terpisah.

### Batas penerapan dan kekeliruan yang perlu dihindari

Method berawalan underscore ditujukan untuk internal. Contoh pemanggilan langsung berguna untuk membaca aturan, tetapi alur pengguna tetap melalui method publik. update_quantity mempunyai semantik hapus untuk integer <= 0; jangan menyalin aturan tambah ke semua endpoint tanpa membaca konteks.

### Latihan penelusuran

Mengapa _validate_quantity tidak membutuhkan self? Apa yang terjadi jika _lines dijadikan list mutable pada tingkat class?

## Kasus 2. Factory budget memakai cls dan memvalidasi hasil rekonstruksi

**Berkas utama:** [recommendation/services/budget.py](../../recommendation/services/budget.py#L81). **Simbol yang dibedah:** `BudgetConstraint.from_dict`.

### Masalah yang dihadapi

Data sesi perlu dapat diserialisasi, sedangkan aturan budget menggunakan Decimal dan property. from_dict menjembatani dictionary yang disimpan dengan object domain yang ingin dipakai program. Membaca state dari penyimpanan bukan alasan melewati validasi constructor.

### Cuplikan kode nyata

Cuplikan `BudgetConstraint.from_dict` dari source saat penyelarasan; bagian berikutnya dilanjutkan di berkas sumber. Import dan bagian lain tidak ditampilkan.

```python
@classmethod
def from_dict(cls, data: BudgetPayload) -> Self:
    try:
        if set(data) != {"minimum", "maximum", "minimum_inclusive", "maximum_inclusive"}:
            raise ValueError("Invalid budget fields")

        if any(
            type(data[key]) is not bool for key in ("minimum_inclusive", "maximum_inclusive")
        ):
            raise ValueError("Invalid budget flags")

        if any(
            data[key] is not None and not isinstance(data[key], str)
            for key in ("minimum", "maximum")
        ):
            raise ValueError("Invalid budget amount")

```

### Bedah alur dan tanggung jawab

1. Baca @classmethod dan parameter cls.
2. Periksa syarat himpunan kunci, tipe flag bool, serta nominal berbentuk str atau None.
3. Ikuti konversi string menjadi Decimal sebelum return cls(...).
4. Bandingkan to_dict: instance method ini memakai state object untuk menghasilkan bentuk penyimpanan.

### Contoh input dan hasil yang perlu dijelaskan

Dictionary dengan minimum=None, maximum="20000", minimum_inclusive=True, maximum_inclusive=True dapat direkonstruksi menjadi budget. Jika maximum berupa angka 20000, bentuk tersebut ditolak karena kontrak penyimpanannya meminta string. Jika minimum "30000" melebihi maximum "20000", constructor tetap menolak rentang.

### Hubungan dengan konsep OOP

Classmethod berfungsi sebagai jalur pembentukan alternatif. cls menunjuk class penerima, bukan object budget yang sudah ada. Pasangan to_dict/from_dict memperlihatkan perbedaan mengubah representasi dan membuat object baru. Return type Self menjelaskan hubungan hasil dengan class penerima.

### Batas penerapan dan kekeliruan yang perlu dihindari

Type hint TypedDict mendokumentasikan bentuk data, tetapi pemeriksaan runtime di from_dict tetap penting. Deserialisasi bukan sekadar menyalin atribut. Menangkap error lalu menerima rentang rusak akan mematahkan invariant yang ingin dijaga.

### Latihan penelusuran

Bandingkan BudgetConstraint.from_dict(data) dengan budget.to_dict(). Mengapa yang satu membutuhkan cls dan yang lain self?

## Kasus 3. Normalisasi alias tidak membutuhkan state model

**Berkas utama:** [menu/models.py](../../menu/models.py#L106). **Simbol yang dibedah:** `MenuItemAlias.normalize_phrase`.

### Masalah yang dihadapi

Dua staf mungkin menulis alias dengan kapitalisasi dan spasi berbeda. Agar pencocokan konsisten, normalisasi hanya memerlukan teks masukan; belum perlu ada object MenuItemAlias yang tersimpan. Karena itu helper diletakkan sebagai staticmethod.

### Cuplikan kode nyata

Cuplikan `MenuItemAlias.normalize_phrase` dari source saat penyelarasan. Import dan bagian lain tidak ditampilkan.

```python
@staticmethod
def normalize_phrase(value: str) -> str:
    return " ".join(value.casefold().split())
```

### Bedah alur dan tanggung jawab

1. Baca @staticmethod dan parameter value.
2. Telusuri casefold lalu split dan join untuk normalisasi kapital/spasi.
3. Buka clean: self.phrase diganti dengan hasil normalisasi dan diperiksa panjang/isinya.
4. Buka save: clean dipanggil sebelum super().save, sehingga jalur simpan model ini juga menggunakan normalisasi.

### Contoh input dan hasil yang perlu dijelaskan

MenuItemAlias.normalize_phrase("  AYAM   Geprek  ") menghasilkan "ayam geprek". Tidak terjadi query dari helper tersebut. Setelah dipakai clean pada satu instans, self.phrase berubah pada instans itu. Simpan tetap terkait menu_item serta constraint unik per menu/phrase.

### Hubungan dengan konsep OOP

Staticmethod mengelompokkan fungsi dengan konsep yang dilayaninya tanpa membuat dependency instans palsu. Instance method clean membutuhkan self karena membaca dan memperbarui field model. Nama yang sama pada helper bukan method khusus Python; decorator-lah yang menjelaskan cara binding-nya.

### Batas penerapan dan kekeliruan yang perlu dihindari

Normalisasi bukan jaminan alias unik di seluruh katalog dan bukan pembersih semua input berbahaya. Beberapa menu dapat memiliki alias serupa sehingga resolver perlu klarifikasi. Aturan bisnis tidak boleh disimpulkan hanya dari nama normalize_phrase.

### Latihan penelusuran

Tunjukkan bagian yang murni menghitung teks dan bagian yang mengubah instans. Mengapa normalisasi tidak otomatis memilih menu yang benar?

## Kasus 4. Property harga dan method total mempunyai peran berbeda

**Berkas utama:** [menu/selection.py](../../menu/selection.py#L101). **Simbol yang dibedah:** `MenuSelection.unit_price`.

### Masalah yang dihadapi

Tampilan membutuhkan harga satuan, sementara transaksi membutuhkan total untuk jumlah tertentu. MenuSelection memakai property untuk nilai turunan dari pilihan yang sudah ada dan instance method untuk perhitungan yang memerlukan parameter quantity.

### Cuplikan kode nyata

Cuplikan `MenuSelection.unit_price` dari source saat penyelarasan. Import dan bagian lain tidak ditampilkan.

```python
@property
def unit_price(self) -> Decimal:
    return (
        self.item.price
        + sum((option.price_adjustment for option in self.__options), Decimal())
        + sum((addon.price for addon in self.__addons), Decimal())
    )
```

### Bedah alur dan tanggung jawab

1. Baca @property pada unit_price lalu identifikasi tiga komponen penjumlahannya.
2. Perhatikan nilai awal Decimal pada sum agar perhitungan uang tetap sesuai tipe.
3. Buka total_price(quantity): input harus integer 1–99 sebelum perkalian.
4. Bandingkan cara akses selection.unit_price dan selection.total_price(2).

### Contoh input dan hasil yang perlu dijelaskan

Dengan harga dasar Rp18.000, varian +Rp2.000, dan addon Rp3.000, property bernilai Rp23.000 dan total_price(2) Rp46.000. total_price(True) ditolak. Memanggil selection.unit_price() keliru karena hasil getter merupakan Decimal, bukan fungsi yang harus dipanggil lagi.

### Hubungan dengan konsep OOP

Property memberi antarmuka baca yang ringkas sambil tetap menghitung nilai. Method biasa menyatakan pekerjaan yang membutuhkan argumen tambahan. Keduanya dapat membaca self; @property tidak mengubah perhitungan menjadi atribut penyimpanan otomatis atau cache.

### Batas penerapan dan kekeliruan yang perlu dihindari

Object katalog di dalam selection tetap dapat berubah. Membaca property bukan janji nilainya abadi. Pemakai harus memahami apakah datanya telah diambil ulang dari database; harga final checkout mengikuti validasi layanan transaksi.

### Latihan penelusuran

Apakah unit_price disimpan sebagai field pada MenuSelection? Mengapa quantity cocok menjadi parameter total_price?

## Kasus 5. Property ketersediaan provider dan method dispatch

**Berkas utama:** [recommendation/services/gemini.py](../../recommendation/services/gemini.py#L29). **Simbol yang dibedah:** `GeminiClient.available`.

### Masalah yang dihadapi

Program perlu membedakan provider siap dipakai dengan permintaan API yang benar-benar dilakukan. available hanya menyatakan flag aktif dan client telah dibuat; generate/converse baru menjalankan alur panggilan yang mempunyai validasi, batas penggunaan, dan pencatatan.

### Cuplikan kode nyata

Cuplikan `GeminiClient.available` dari source saat penyelarasan. Import dan bagian lain tidak ditampilkan.

```python
@property
def available(self) -> bool:
    return bool(getattr(settings, 'GEMINI_ENABLED', False) and self.client is not None)
```

### Bedah alur dan tanggung jawab

1. Baca constructor: client awalnya None dan hanya dibentuk ketika flag serta key tersedia.
2. Baca available sebagai property bool.
3. Ikuti generate ke _generate dan converse ke loop SDK.
4. Temukan _allow_provider sebelum dispatch dan provider_event sesudah respons atau error.

### Contoh input dan hasil yang perlu dijelaskan

Ketika GEMINI_ENABLED=False, available False dan tidak ada SDK dispatch. Ketika flag aktif dan client ada, available dapat True, tetapi kuota masih bisa menolak panggilan. Karena itu available tidak berarti satu permintaan pasti akan menghasilkan jawaban sukses.

### Hubungan dengan konsep OOP

Getter menerangkan keadaan yang dapat diperiksa pemanggil tanpa membuka detail seluruh adapter. Method generate menerima pekerjaan, sedangkan helper _allow_provider memusatkan kebijakan sebelum pekerjaan dilakukan. Atribut last_event menyimpan metadata upaya terakhir, bukan seluruh riwayat.

### Batas penerapan dan kekeliruan yang perlu dihindari

available tidak memverifikasi key ke Google dan bukan uji koneksi. Membaca property tidak memanggil model. Log total token baru tersedia setelah respons; nilai null berarti belum diketahui. Jangan menjalankan API asli sekadar untuk membuktikan property.

### Latihan penelusuran

Bedakan available=True, provider_called=True, dan outcome=success. Apakah ketiganya selalu muncul bersamaan?
