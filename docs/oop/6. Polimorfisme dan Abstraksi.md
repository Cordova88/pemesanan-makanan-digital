# Modul 6. Polimorfisme dan Abstraksi

[Kembali ke indeks OOP](README.md). Diselaraskan dengan source project utama, 23 Oktober 2026.

Pemanggilan generate dapat dijalankan adapter Gemini atau wrapper giliran; str dapat menampilkan menu atau grup varian; == dapat membandingkan nilai budget. Polimorfisme memusatkan cara pemanggilan sambil membiarkan implementasi berbeda. Abstraksi menentukan janji yang cukup bagi pemakai dan menyembunyikan detail yang tidak dibutuhkan pada batas tersebut.

## Tujuan pembelajaran

- Membedakan kontrak abstrak, override, dan dispatch runtime.
- Menjelaskan polimorfisme method biasa maupun special method Python.
- Memeriksa kebutuhan nyata caller sebelum mengganti suatu implementasi.

## Bekal istilah

| Istilah | Makna saat membaca kode |
|---|---|
| ABC/abstractmethod | Kontrak formal yang membatasi instansiasi class yang belum lengkap. |
| Dispatch | Pemilihan implementasi berdasarkan object penerima saat runtime. |
| Special method | Method seperti `__str__` dan `__eq__` yang digunakan protokol Python. |
| Kontrak perilaku | Input, output, kondisi gagal, dan efek yang perlu dipahami caller. |

## Kasus 1. TextGenerator menyatakan janji minimum pembuat teks

**Berkas utama:** [recommendation/services/text_generator.py](../../recommendation/services/text_generator.py#L6). **Simbol yang dibedah:** `TextGenerator`.

### Masalah yang dihadapi

Layanan penjelasan ingin meminta teks, bukan mengatur SDK dan autentikasi provider. TextGenerator menyatakan kontrak generate(prompt) → str | None. Abstraksi ini membuat caller bisa fokus memeriksa teks hasilnya.

### Cuplikan kode nyata

Cuplikan `TextGenerator` dari berkas sumber. Import dan bagian lain tidak ditampilkan.

```python
class TextGenerator(ABC):
    @abstractmethod
    def generate(self, prompt: str) -> str | None:
        """Return response text, or None when generation is unavailable/failed.

        Provider adapters handle their own provider/network failures. Consumers
        remain responsible for parsing and validating the returned text.
        """

        raise NotImplementedError

    def generate_ranking(self, prompt: str) -> str | None:
        """Optional ranking format support; text-only providers keep their behavior."""

        return self.generate(prompt)
```

### Bedah alur dan tanggung jawab

1. Baca pewarisan ABC dan decorator abstractmethod.
2. Temukan signature generate serta docstring kondisi unavailable/failed.
3. Baca generate_ranking yang secara default meneruskan ke self.generate.
4. Bandingkan implementasi konkret GeminiClient dan TurnGenerator.

### Contoh input dan hasil yang perlu dijelaskan

TextGenerator sendiri belum dapat diinstansiasi karena generate abstrak. Subclass yang mengisi generate dapat menjadi generator konkret. Memanggil generate_ranking bawaan pada subclass itu akan memakai implementasi generate milik object aktual melalui self.

### Hubungan dengan konsep OOP

Abstraksi menghilangkan kebutuhan caller mengetahui transport jaringan pada batas ini. Polimorfisme muncul ketika caller yang sama memanggil generate pada object konkret berbeda. Kewajiban caller tetap mencakup parsing dan validasi keluaran; kontrak teks bukan kontrak fakta pasti benar.

### Batas penerapan dan kekeliruan yang perlu dihindari

ABC tidak otomatis memeriksa semantic return runtime dan tidak menjamin kualitas bahasa. Kontrak ini tidak mempunyai converse, available, atau tool handler. AI-first membutuhkan kemampuan tambahan, sehingga dependency injection bertipe TextGenerator pada bagian lain belum berarti semua generator bisa dipertukarkan di sana.

### Latihan penelusuran

Apa beda gagal membuat instans abstract class dengan provider konkret yang mengembalikan None?

## Kasus 2. Wrapper memilih perilaku melalui object provider

**Berkas utama:** [recommendation/services/ai/turn_generator.py](../../recommendation/services/ai/turn_generator.py#L69). **Simbol yang dibedah:** `TurnGenerator._generate`.

### Masalah yang dihadapi

Komponen penjelasan dan ranking dapat memakai wrapper yang sama. Wrapper memeriksa jatah lalu meneruskan ke provider. Caller tidak perlu mengetahui apakah provider memakai API asli atau implementasi uji yang memenuhi kontrak.

### Cuplikan kode nyata

Cuplikan `TurnGenerator._generate` dari berkas sumber. Import dan bagian lain tidak ditampilkan.

```python
def _generate(self, prompt: str, *, ranking: bool) -> str | None:
    if self._private or not self._reserved or self._attempted:
        return None

    # Claim before dispatch; exceptions and invalid results cannot refund it.
    self._attempted = True

    try:
        if ranking and isinstance(self.provider, TextGenerator):
            return self.provider.generate_ranking(prompt)

        return self.provider.generate(prompt)
    except Exception:
        return None
```

### Bedah alur dan tanggung jawab

1. Baca generate dan generate_ranking yang memilih flag ranking.
2. Ikuti gate _private, _reserved, dan _attempted di _generate.
3. Periksa isinstance(provider, TextGenerator) untuk jalur generate_ranking.
4. Ikuti provider.generate(prompt) dan hasil None ketika error ditangani.

### Contoh input dan hasil yang perlu dijelaskan

Untuk provider turunan TextGenerator yang hanya mengisi generate, generate_ranking bawaan akhirnya tetap menjalankan generate tersebut. Untuk provider yang meng-override generate_ranking, wrapper memakai implementasi khususnya. Satu bentuk pemanggilan dapat memilih perilaku berbeda sesuai object.

### Hubungan dengan konsep OOP

Ini menggabungkan delegation dan polimorfisme. Wrapper tidak harus berisi if untuk setiap nama model/provider, selama object memenuhi kontrak yang dipakai. Gate tetap berjalan sebelum delegation sehingga variasi implementasi tidak otomatis menghindari kebijakan wrapper.

### Batas penerapan dan kekeliruan yang perlu dihindari

Object palsu dengan method generate belum tentu memenuhi semua kebutuhan chatbot. Khusus assistant, tersedia akses available/converse. Selain itu, reservasi wrapper merupakan bagian penggunaan yang perlu diikuti; mengganti provider tidak menghapus prasyarat tersebut.

### Latihan penelusuran

Telusuri generate_ranking jika provider hanya mengimplementasikan generate. Method mana yang akhirnya dipanggil dan mengapa?

## Kasus 3. str menampilkan representasi model yang sesuai object

**Berkas utama:** [menu/models.py](../../menu/models.py#L142). **Simbol yang dibedah:** `VariantGroup.__str__`.

### Masalah yang dihadapi

Pilihan dalam form admin perlu dibaca sebagai nama yang bermakna. Python memanggil `__str__` ketika object dikonversi ke teks. Setiap model menentukan representasinya tanpa memaksa seluruh caller menulis percabangan tipe.

### Cuplikan kode nyata

Cuplikan `VariantGroup.__str__` dari berkas sumber. Import dan bagian lain tidak ditampilkan.

```python
def __str__(self) -> str:
    return f"{self.menu_item}: {self.name}"
```

### Bedah alur dan tanggung jawab

1. Baca MenuItem.`__str__` yang mengembalikan self.name.
2. Baca MenuTag.`__str__` yang memilih display_name atau name.
3. Periksa VariantGroup.`__str__` yang menggabungkan menu_item dan nama grup.
4. Amati f-string di dalamnya: representasi menu_item juga memakai protokol string model terkait.

### Contoh input dan hasil yang perlu dijelaskan

Dengan menu bernama Nasi dan grup bernama Ukuran, str(grup) dapat menjadi "Nasi: Ukuran". str(menu) menjadi "Nasi". Caller memanggil str dengan cara sama, tetapi runtime memilih special method sesuai class object. Contoh nama ini ilustrasi, bukan query katalog.

### Hubungan dengan konsep OOP

Polimorfisme tidak selalu harus memakai ABC buatan proyek. Special method merupakan protokol Python yang dapat disesuaikan class. Override di model proyek memanfaatkan perilaku framework untuk label tampilan, sedangkan isi string dipilih tim.

### Batas penerapan dan kekeliruan yang perlu dihindari

`__str__` bukan serializer API atau ID unik. Dua menu bisa mempunyai nama sama dan perubahan label tidak otomatis mengubah primary key. Mengakses relasi untuk menyusun string juga berpotensi memerlukan query bila belum dimuat; representasi sederhana tetap mempunyai konteks biaya.

### Latihan penelusuran

Mengapa str(menu) dan str(grup) tidak membutuhkan if isinstance pada caller? Apakah hasil string cocok dijadikan kunci transaksi?

## Kasus 4. Operator sama dengan memakai kesamaan nilai budget

**Berkas utama:** [recommendation/services/budget.py](../../recommendation/services/budget.py#L107). **Simbol yang dibedah:** `BudgetConstraint.__eq__`.

### Masalah yang dihadapi

Dua bagian program dapat merekonstruksi budget dari sesi yang sama menjadi dua instans berbeda. Untuk mengetahui apakah batasnya setara, perbandingan identitas tidak cukup. `__eq__` menentukan persamaan berdasarkan empat komponen nilai budget.

### Cuplikan kode nyata

Cuplikan `BudgetConstraint.__eq__` dari berkas sumber. Import dan bagian lain tidak ditampilkan.

```python
def __eq__(self, other: object) -> bool:
    return isinstance(other, BudgetConstraint) and (
        self.minimum,
        self.maximum,
        self.minimum_inclusive,
        self.maximum_inclusive,
    ) == (other.minimum, other.maximum, other.minimum_inclusive, other.maximum_inclusive)
```

### Bedah alur dan tanggung jawab

1. Baca pemeriksaan isinstance(other, BudgetConstraint).
2. Bandingkan tuple minimum, maximum, dan flag inclusive pada kedua object.
3. Buka `__hash__` yang memakai komponen nilai yang sama.
4. Bedakan operator == dengan is yang membandingkan identitas object.

### Contoh input dan hasil yang perlu dijelaskan

Dua BudgetConstraint(maximum=Decimal("10000")) yang dibuat terpisah dapat memenuhi a == b walaupun a is b False. Jika satu memakai maximum_inclusive=False, nilai persamaannya berbeda. Batas eksklusif bukan detail kosmetik karena harga tepat pada batas menghasilkan keputusan allows berbeda.

### Hubungan dengan konsep OOP

Python menerjemahkan operator ke protokol method khusus. Class menyatakan arti "sama" bagi domainnya, sehingga caller tidak harus membandingkan field satu per satu. Konsistensi komponen `__eq__`/`__hash__` penting ketika object dipakai pada struktur berbasis hash.

### Batas penerapan dan kekeliruan yang perlu dihindari

Kesamaan nilai tidak berarti object berbagi penyimpanan atau pengguna yang sama. Tidak ada janji bahwa semua class boleh dibandingkan sebagai budget. Walaupun property tidak mempunyai setter publik, mutasi internal secara paksa masih dapat merusak asumsi object bernilai stabil.

### Latihan penelusuran

Bandingkan == dan is untuk dua budget identik. Mengapa flag inclusive harus ikut dibandingkan?

## Kasus 5. Form merender widget sesuai implementasi turunannya

**Berkas utama:** [menu/widgets.py](../../menu/widgets.py#L12). **Simbol yang dibedah:** `MenuPhotoWidget.get_context`.

### Masalah yang dihadapi

Form memakai antarmuka widget Django untuk menampilkan input. Ketika field diberi MenuPhotoWidget, pemanggilan get_context memilih override proyek. Caller form tetap memakai mekanisme widget yang sama tanpa perlu merinci semua logic preview.

### Cuplikan kode nyata

Cuplikan `MenuPhotoWidget.get_context` dari berkas sumber. Import dan bagian lain tidak ditampilkan.

```python
def get_context(
    self,
    name: str,
    value: File | None,
    attrs: dict[str, object] | None,
) -> dict[str, object]:
    context = super().get_context(name, value, attrs)
    context["widget"]["photo_url"] = value.url if value and hasattr(value, "url") else ""

    return context
```

### Bedah alur dan tanggung jawab

1. Baca inheritance ClearableFileInput dan signature get_context.
2. Ikuti pemanggilan super agar struktur dasar dipertahankan.
3. Temukan penambahan photo_url.
4. Buka menu/forms.py untuk melihat field yang benar-benar menggunakan widget tersebut.

### Contoh input dan hasil yang perlu dijelaskan

Field image dan detail_image memasang widget khusus. Saat dirender, kedua field mendapatkan context yang diperluas. Input tanpa foto memperoleh photo_url kosong; input dengan file tersimpan memperoleh URL. Perilaku pemilihan override ditentukan object widget yang dipasang pada field.

### Hubungan dengan konsep OOP

Kasus ini menunjukkan dispatch framework: abstraksi widget menyediakan titik perluasan dan turunan mengisi bagian khusus. Caller tidak harus menulis renderer alternatif untuk setiap field. Super mempertahankan bagian kontrak konteks yang sudah disediakan induk.

### Batas penerapan dan kekeliruan yang perlu dihindari

Kesamaan nama method saja belum menjamin substitusi: struktur context tetap harus cocok dengan template/framework. Widget juga tidak bisa dianggap pengganti validator file; preview berhasil tidak membuktikan file memenuhi batas server.

### Latihan penelusuran

Bagaimana hasilnya jika field memakai ClearableFileInput biasa? Bagian perilaku mana yang hilang dan mana yang tetap ada?
